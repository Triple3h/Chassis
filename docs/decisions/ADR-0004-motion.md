# ADR-0004：动效语言 —— 令牌单一来源 + 窗口离场由内核收口

- 状态：已采纳
- 日期：2026-09-16
- 相关：`docs/launcher-requirements.md` §3.1 / §3.2 / §6.2；`apps/launcher-ui/src/styles/app.css`；`packages/ui/styles/theme.css`

## 背景

启动台是对标 macOS 面板类应用的常驻工具，"唤出来那一下"就是它的第一印象。改造前实测的现状：

- **窗口完全没有显隐动画**：壳 `show()` / `hide()` 都是瞬时的。UI 早已订阅 `shell/visibility`，但收到即忽略。
- **时长散落无处可查**：`0.12s` / `0.14s` / `0.15s` / `0.18s` 与 Tailwind 默认 `150ms` 混用，缓动在 `ease` / `ease-out` / `ease-in-out` 之间随机。
- **`prefers-reduced-motion` 全仓库 0 处**。
- 二级面板只有进场没有离场；右键菜单、toast、插件视图、插件侧对话框完全没有动效；窗口高度随结果行数瞬跳。

窗口本身是 `transparent(true)` + `decorations(false)`，视觉上只有 `.shell` 这层圆角半透明面板会被画出来 ——
所以"窗口弹出"完全可以在 CSS 里做，不需要壳参与绘制。

> 2026-09-16 补：`.shell` 上原本还有一层 `backdrop-filter` 毛玻璃。它在 `border-radius` 之外会漏出像素，
> 而 macOS 的系统窗口阴影是按「内容的 alpha 轮廓」生成的 —— 角落一有像素，阴影就退化成矩形（底角出现
> 与圆角对不齐的直角灰边）。已移除该属性，取舍写在 `apps/launcher-ui/src/styles/app.css` 的注释里。

## 决策

### 1. 令牌是唯一来源，降级只改令牌

两处 `:root` 各一份同值令牌（宿主 `--motion-*`、插件 `--launcher-motion-*`）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--motion-instant` | 90ms | 按压、hover、状态色 |
| `--motion-fast` | 140ms | 离场、小元件 |
| `--motion-base` | 200ms | 进场、面板 |
| `--motion-slow` | 320ms | 大块内容（骨架） |
| `--motion-ease-enter` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进场：强减速"落到位" |
| `--motion-ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 离场：加速"果断走" |
| `--motion-ease-move` | `cubic-bezier(0.4, 0, 0.2, 1)` | 位移 / 颜色 |
| `--motion-ease-spring` | `cubic-bezier(0.34, 1.4, 0.64, 1)` | 只给"弹出"用（轻微过冲） |

两条硬规矩：

- **离场一定比进场短。** 离场是用户已经在等结果的动作，拖长只会让人觉得卡。
- **`prefers-reduced-motion` 只重定义令牌本身**：缩放归 1、位移归 0，**时长只压短、不归零**
  （120 / 150 / 180ms），组件里不再写第二遍媒体查询。保留淡入淡出是刻意的 ——
  那是位移之外的过渡，无障碍规范普遍接受；全压成 1ms 等于把动效整个丢掉
  （2026-09-16 修正：旧写法就是 1ms，开了「减弱动态效果」的用户看到的是硬跳）。

命名刻意避开 `--ease-*` / `--duration-*`：那是 Tailwind v4 的主题命名空间，同名会被覆盖。

### 2. 窗口显隐拆成「广播」和「落地」两步，落在内核

```
壳 show/hide ──► window/toggled{visible} ──► 内核 emit shell/visibility ──► UI 播动画
                                  ↑
内核自己发起：showWindowAnimated() / hideWindowAnimated()
```

- **`window/toggled` 的方向不变**：壳仍然是显隐的唯一裁决者，内核只广播、绝不 toggle（ADR 之前的不变量，测试仍在守）。
- **隐藏以「UI 回执」收尾（2026-09-16 改）**：`hideWindowAnimated()` 先 `emit('shell/visibility', {visible:false})`
  让 UI 播 140ms 的淡出 + 缩放，**等 UI 回执「离场最后一帧画出来了」（`POST /api/window/hidden`）才真去敲壳**；
  `HIDE_FALLBACK_MS`(500ms) 只是「回执永远不来」的兜底。
  旧写法是隔固定 130ms 落地 —— 那段时间要同时盖住「IPC + SSE + webview 取事件」的不可控延迟和 140ms 淡出，
  一旦被砍在中间，webview 就把**半透明的一帧**留成「最后一帧」，下次唤出合成器先亮它
  （实测反馈：「闪一下，像打开了两次」）。回执把「演完了」交给唯一知道答案的一方。
- **显示反过来「晚一点广播」（2026-09-16 补）**：壳的 `show()` 返回 ≠ 窗口上屏 + webview 恢复绘制，
  而 CSS 的时间线不会等 —— 立刻广播会让入场动画在窗口还没有画面时播完（实测反馈："动效好像没实现"）。
  内核 `emitVisibleAnimated()` 推迟 `SHOW_ANIMATION_MS`(80ms) 再广播（带令牌：排队期间又被隐藏就作废）；
  隐藏那条仍然立刻广播，因为那时窗口还看得见、离场动画正常播。
- **壳自己发起的隐藏同样只报告意图（2026-09-16 改）**：热键 toggle、托盘左键、`⌘W` 以前是直接
  `window.hide()` —— webview 会冻结在「完整面板」那一帧（离场动画根本来不及渲染），
  下次唤出时合成器先把旧画面亮出来，用户看到的是「闪一下，像打开了两次」。
  现在统一走 `window::toggle()` → `notify_toggled(false)` + `arm_hide_fallback()`（800ms 兜底，
  防「内核没起来 / 失联」时没人回执），真正的 `hide()` 由内核在回执之后发起；
  「离场途中再按一次」= 取消隐藏（窗口这时仍然可见，壳里用一个「计划落地时间戳」当令牌）。
- **队列中的隐藏可以被撤销**：`cancelPendingHide()` 换一个令牌，回执 / 兜底到点发现令牌被换过就自己退出 ——
  **迟到的回执也不能把窗口偷走**。必须在两处调用 —— 内核自己 `showWindowAnimated()` 时，
  以及壳报来 `window/toggled{visible:true}` 时。少了后者就是「热键连按 → 窗口被上一次隐藏偷走」。
- **重复调用搭同一班车**：一次 `ctx.hostUi.hide` 会同时从内核和 UI 两条路走回来，只会落地一次。
- 同一高度重复请求、`prefers-reduced-motion`、幅度 > 280px 时，`windowMotion.ts` 直接落位不缓动。

### 3. 所有显隐路径都必须回报结果

改这条时发现壳有两条路径改完显隐**不通知内核**，在"隐藏态是透明的"新前提下会直接白屏，已一并修掉：

| 路径 | 原来的问题 |
|---|---|
| 托盘菜单「唤出启动台」 | 只 `show()` 不回报 ⇒ UI 停在透明态 |
| 单实例二次启动（`single_instance`） | 只 `show()` 不回报 ⇒ 同上 |
| `CloseRequested`（`⌘W`） | 只 `hide()` 不回报 ⇒ UI 以为还可见，下次唤出没有入场动画 |

规律可以推广成一句话：**谁真正改了跨进程共享的状态，谁就必须把结果报回来。**

### 4. 用「两个稳定态之间做 transition」，不用 keyframes 重放

`.shell` 的隐藏态（`opacity: 0` + `scale(0.94) translateY(-10px)`，落差对齐聚焦搜索）本身是一个静止态，
显隐就是在这两个态之间做 `transition`。刻意不选 keyframes 动画，是因为要避开两个坑：

- 重放动画需要"移除类 → 强制重排 → 加回类"那套 hack；
- 窗口被壳提前隐藏时 webview 会暂停渲染，动画可能卡在中途，元素就永远停在半透明。

**入场这条路的坑（2026-09-16 补）**：`transition` 要求「起点已经被渲染过」，而窗口被藏起来时
webview 的绘制是挂起的、CSS 的时钟却照走 —— 于是「壳显示窗口 → UI 立刻摘掉隐藏态」这套顺序
会在绘制恢复之前把动画走完，用户看到的只是「啪」一下整块出现（实测反馈：动效好像没实现）。
现在 UI 侧统一走 `setWindowVisible()`：隐藏立即做，显示要**先等页面可见**（`visibilitychange`，
带 400ms 兜底）**、再等 `waitForPaint()`**（页面可见后等两帧 —— rAF 重新跑起来本身就说明帧循环转了；
另有 120ms 上限与 setTimeout 保险 —— 白屏比没有动画严重得多），然后才摘掉隐藏态；内核侧同时把显示广播
推迟 `SHOW_ANIMATION_MS` 再发。窗口焦点兜底也走同一条路径，不会把动画抢跑。

> **2026-09-16 修正**：`waitForPaint` 原来抓「恢复后的第一个长帧」（上限 200ms），实测录屏里
> 那段时间是**空窗**：旧画面已被擦掉、动画还没开始，用户先干等 200ms。
> rAF 回调本身已经是「在画」的证据，抓长帧属于过度设计，已改掉。

同理，所有 Vue `<Transition>` 都显式传 `:duration`，收尾走定时器而不是 `transitionend`。

## 后果

**收益**

- 唤出/收起有了完整的弹出感；二级面板、右键菜单、toast、插件视图、插件对话框全部对齐同一手感。
- 想调整整体节奏只改 8 个数值；降级只改一处。
- 修掉了三条"改完显隐不回报"的路径（其中两条原本会导致白屏）。

**代价**

- 隐藏的落地时点由 UI 的回执决定（≈离场时长 + 100ms）。这是刻意的取舍：换来的是不"啪"地消失，
  也不把半透明的一帧留成「下一场唤出先亮的旧画面」；回执不来时有 500ms 兜底，壳侧另有 800ms 兜底防内核失联。
- 窗口高度改为逐帧 `setHeight`（约 10 次 IPC / 160ms）。顺序发送、每帧一次，不并发 ——
  并发会让壳侧的到达顺序不确定，窗口会来回抖。
- `HideAnimation` 让"隐藏"不再是同步操作：任何新的隐藏入口都必须走 `hideWindowAnimated()`（内核侧）
  或 `window::toggle()`（壳侧），否则回执链路会断，窗口要么不落地、要么闪旧画面。

## 备选方案与不采纳原因

| 方案 | 不采纳原因 |
|---|---|
| 壳侧加 `set_opacity` / NSWindow 动画 | 壳要保持零业务；且 CSS 已经能画，多一条跨进程通道只增加同步负担 |
| UI 侧 hold 住 hide（先演再让内核隐藏） | 不采纳的是「UI 说了算」：裁决权会分裂到两个进程，正是 §6.2 明确否掉的形态。**回执不是裁决** —— UI 只说「动画演完了」，落地仍由内核决定（且带兜底），壳侧同样保留 800ms 兜底 |
| 隐藏保持瞬时（Raycast 的做法） | 与"弹入"不对称；实测观感是"唤出很顺、关闭很生硬" |
| 结果格子逐条错峰进场 | 搜索是 80ms 防抖 + 每次按键都换内容，错峰会和下一次按键的动画叠在一起，看着更乱 |
| 用 `@starting-style` / `allow-discrete` 做卸载动画 | 解决的是 `display` 过渡，管不了组件真正被卸载的场景 |
| 插件侧对话框改造成受控 `open` prop 以拿到离场 | `ImportDialog` / `SaveDialog` 依赖 `onMounted` 做摄像头与自动聚焦初始化，改成常驻会改变行为；先只补进场 |
