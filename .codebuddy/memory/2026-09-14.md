### 踩到的坑（值得记住）

1. **插件根识别**：`<dir>/dist/package.json` 存在时，插件根 = `<dir>/dist`（源码工程 vs 安装形态），`scan()` 与 `installFromDirectory()` 必须用同一规则，否则出厂插件全部 `ENTRY_MISSING`。
2. **产物自包含**：`simple-plist` 内部 `require('bplist-creator')` 打不进 bundle → 破坏 N1。改自研 `plugins/app-launcher/src/core/plist.ts`（binary + XML），并在 `build-plugin.mjs` 加校验（产物只能出现 `node:*`）。
3. **binary plist 的字符串是 UTF-16BE**，按 LE 读会得到 `匀愀昀愀爀椀…` 这类乱码。
4. **冒烟必须用新构建的产物**：我第一次跑冒烟失败，原因是 `apps/kernel/dist/kernel.mjs` 是改动前构建的。
5. 契约/单元测试通过 `scripts/run-ts.mjs`（esbuild bundle 到 `.dev/`）运行，必须 **bundle**（不能用 `packages: 'external'`），否则 workspace 包在 `.dev/` 下解析不到。

### 严重 bug：装好后"只有托盘图标，怎么都唤不出窗口"（已修）

**根因（字段名不匹配，一处错导致链式失败）**：
壳启动后轮询内核 `kernel/ready` 拿 UI 端口，内核回的是 `{ ok:true, ui: <port> }`，而 Rust 侧读 `value.get("uiPort")` ⇒ 永远取不到 ⇒ 25s 后超时 ⇒ **同一个分支里的 `hotkey::register` 从未执行**（热键完全没注册）、**`window.navigate()` 从未执行**（窗口一直停在 ui-stub 的"正在启动内核…"页）。

诊断证据：审计日志里只有 `context.mount`（装配期），但有 `history.json` ⇒ 用户点过托盘菜单、命令确实执行了，只是 UI 从未被导航过去。

**修复（5 处）**：
1. 内核 `kernel/ready` 统一返回 `{ ok, ready, uiPort, version, dataRoot }`；壳侧兼容 `uiPort` / `ui`，且要求 `ready===true && port>0`
2. 内核加就绪标志 `markReady()/isReady`（否则内核还没 `listen()` 就被问端口会返回 0）
3. **热键与内核解耦**：壳在 setup 里先注册热键（不等内核），内核就绪后按配置重注册
4. **热键自动回退**：`Alt+Space` 在 macOS 常被输入法占用 ⇒ 失败后依次试 `Ctrl+Space`→`Cmd+Shift+Space`→`Cmd+Alt+Space`→`Ctrl+Alt+Space`→`F1`→`Shift+F1`，并**把实际生效的键写回 config** + 发系统通知
5. **壳日志落盘** `<dataRoot>/logs/shell.log`（GUI 启动时 stderr 被系统丢弃，这是唯一排查现场）；启动后 1.5s 发通知"已就绪 + 按 X 唤出"避免"以为没反应"

**连带修复**：
- 内核 SIGTERM 优雅退出加 3s 强制兜底（之前会挂住 → 残留进程需要 `kill -9`）
- 壳被强杀时内核变孤儿 ⇒ 内核监听 stdin `end/close`（非 standalone 模式）自动退出

**自用排查入口**：`~/Library/Application Support/Launcher/logs/shell.log`（含壳与内核全部日志，一个文件看全链路）。

### 下一个 bug：`⌥Space` 唤出的窗口"闪一下就消失"（托盘唤出正常）

**根因**：窗口从隐藏变可见时会先收到一次 `WindowEvent::Focused(false)`（此时 `set_focus()` 尚未生效），120ms 后走失焦隐藏 → 内核 `hideOnBlur: true` → 立刻 `hideWindow()`。托盘点击不会有此问题，因为点击图标本身让 app 成为活跃应用。

**修复（壳侧两道保护，`primitives/window.rs` + `lib.rs`）**：
1. `SHOW_GRACE_MS = 600` 唤出防抖窗口：`mark_shown()` 记录时间戳，窗口 show 后 600ms 内的失焦一律忽略
2. `HAS_FOCUSED` 标记：本次显示后**从未获得过焦点**时也忽略失焦（避免窗口真的抢不到焦点时永远不隐藏）
3. 两条被忽略的路径都写日志（`忽略失焦（唤出防抖窗口内）` / `忽略失焦（本次显示后从未获得焦点）`），便于后续排查

**经验**：任何"失焦即隐藏"的启动器都必须有唤出后的 grace period，否则在 macOS 上必然闪退式隐藏。

## 应用图标（`npm run icon`）

原来的 `apps/shell/icons/icon.png` 是占位图（蓝紫渐变 + 白方块），换成真图标。

**做法**：AI 生成只用来定方向，成品改为**脚本化矢量**——位图在 16px 到 1024px 之间必然糊，且 AI 稿有角形不规则、带水印、底不透明三个硬伤。

**两个字形（刻意不同）**：

| 用途 | 字形 | 理由 |
|---|---|---|
| 应用图标 | 「输入框」= 白色胶囊外框 + 文字光标 + 上箭头 | 表达"输入即搜、回车即启"；用户看了草图后从放大镜改成它 |
| 菜单栏 | 黑色放大镜 | 18pt 下输入框内里的光标/箭头会糊掉，放大镜轮廓干净得多（用户明确要求换回放大镜） |

配色：蓝 `#1C5CF5` → 靛 `#5B34E8` → 亮紫 `#A32BEE`，左下到右上对角 + 右上角紫色辉光 + 底部压暗。

- `scripts/make-icon.mjs`（`npm run icon`）：`icons/icon.svg` → 10 档 PNG → `icon.icns`（iconutil），同时产出 `icon.png(512)` 与 `tray.png(36×36)`
- **圆角用超椭圆**（`SQUIRCLE_N = 5`，采样 72 点/角）而不是 SVG 的 `rect rx`：后者是圆弧角，和 Apple 的连续圆角在 824px 图稿上肉眼可辨
- 设计常量集中在脚本顶部：`PALETTE`、`PLATE = 824`（macOS 图稿标准留白）、`MARK`（输入框尺寸）、`MAGNIFIER`（放大镜尺寸/描边）
- 依赖 `rsvg-convert`（`brew install librsvg`），iconutil 是 macOS 自带

**字形几何的坑（第一版渲染出来是糊的，根因在这）**：输入框的光标和箭头最初按**外框宽度**的百分比定位，胶囊一变窄光标就贴到边框上、和边框糊成一体。改为按**描边中线框**（`frameW/frameH = w/h - stroke`）的百分比定位后成立。
（放大镜没有这个问题：它是方形的，环心 + 45° 手柄，只需把字形框中心挪回原点。）

**菜单栏图标必须是单色模板图**：`tray-icon` 会把整图**高度钳到 18pt**、宽度按比例算，再套 `NSImage.setTemplate`（只取 alpha、按明暗自动反色）。所以①给彩色应用图标是错的；②画布长宽比直接决定占多宽。放大镜是方形 ⇒ 正好 18×18pt。

**菜单栏图标单独做**（`icons/tray.svg` → `tray.png`）：`tray-icon` crate 会把图标强制压到 **18pt** 并用 `NSImage.setTemplate`，所以给彩色应用图标是错的（又糊又不对味）。改成 `include_bytes!` 编译进二进制 + `icon_as_template(true)`，系统只取 alpha 通道按明暗自动反色。

**踩坑**：换 `.icns` 后 Dock/Finder 会一直显示旧图标 ⇒ `pack-local-app.mjs` 打包后追加 `lsregister -f <app>` 刷新 LaunchServices 缓存。

**经验**：菜单栏图标必须是单色模板图；应用图标必须是矢量源 + 脚本生成，否则换配色要重画一堆位图。

## 真正的 bug：`⌥Space` 唤出后窗口立刻消失（第二次修复，这次是根因）

上次加"防抖 grace period"没治好，因为**根因根本不在失焦**。

**根因：一次热键被 toggle 了两遍。**
- 壳 `hotkey.rs::toggle` 自己做了显隐；
- 紧接着 `link.notify('hotkey/pressed')` 通知内核，而内核 `api.ts` 里的同名处理器**又做了一遍** `isVisible() → hideWindow()/showWindow()`。
- 壳刚显示 → 内核查到 `visible=true` → **立刻隐藏**。托盘左键正常，正是因为托盘那条路径完全不经过内核（壳内闭环）。

**定位依据（日志）**：`[hotkey] toggle → visible=true` **每一次按键都出现** —— 说明每次按键时 `is_visible()` 都是 false，即窗口在上一次按键后确实被隐藏了。而壳侧的失焦路径每次都打了"忽略失焦"，说明隐藏不是壳发的。剩下的唯一出口就是内核。

**修复（把"显隐的裁决者"收敛到壳一处）**：
1. `apps/kernel/src/api.ts`：`hotkey/pressed` → **`window/toggled`**，只 `emit('shell/visibility')` 广播状态，**绝不 toggle**（并写了注释说明为什么）
2. `apps/shell/src/primitives/window.rs`：新增 `notify_toggled(app, visible)`（只表达"结果"）
3. `hotkey.rs::toggle` 与 `tray.rs` 左键都改调它；壳自己发起的 `window.show/hide` **不回报**，避免回环
4. `lib.rs`：失焦真正通知内核的那条路径补日志（之前静默，导致排查只能靠推断）

**回归测试**：新增 `tests/contract/shell-link.test.ts` + harness 的**假壳**（`fakeShell: true`，用一对 `PassThrough` 接上内核的 stdio RPC）。它站在壳那一侧断言"内核不得自行隐藏窗口"。**这类"两边都做了一遍"的 bug，只看各自源码是看不出来的**，必须有个东西扮演对端。

**教训**：跨进程的同一件事，必须明确"谁是裁决者、对端只收结果"。防抖/延迟这类补丁治不了重复执行。

### 踩到/确认的坑（写进 `docs/plugin-spec.md` 了）

1. **宿主判定必须探活**：如快的 `inSofastIframe()`（`window.top !== window`）与底座的 `isLauncher()`（iframe + `?sid=`）在**对方宿主里同样为真**。只能各发一次只读探针（`host.info` / `Context.getSearchContent`），300ms 谁先应答就是谁
2. **两边 Node 协议并不相同**（计划里写"完全相同"是错的）：`progress` 字段名（`progress` vs `p`）、`fail` 信封（`{type:'error'}` vs `{type:'result',data:{__error}}`）、`done(undefined)` 行为都不同 → 双宿主脚本要同时发两套
3. **v1 底座在 view 会话打开时不显示搜索框**（插件页占满窗口）⇒ `hostUi.watchSearchContent` 不会有回调；入口型插件只能用 `getSearchContent()` 取初始输入
4. 底座 footer 的 `keys` 只展示不派发快捷键（插件要自己处理键盘）

## 把 4 个插件搬进仓库，作为「预置插件」（presets/）

用户要求：「把这4个插件移进仓库里统一管理吧，作为预置插件，跟 plugins 下的4个内置插件区分开」。

### 结构

```
presets/
├── README.md            定位 / 与 plugins/ 的对比表 / 命令 / 边界
├── CODEBUDDY.md         移植过来的 AI 入口（路径已改到 presets/ 形态）
├── .codebuddy/{rules,skills}/  原仓库的规则与技能（sofast-plugin / sofast-plugin-dev）
├── docs/sofast-plugin-dev-guide.md
├── shared/              适配层 + UI（构建期打进产物）
├── scripts/             build-all / spec-check / vite-shared / manifest-plugin
├── tests/               适配层单测（宿主映射等价性、超时与兜底）
└── sofast-{totp,hosts,text-diff,json-tools}/
```

**与 `plugins/` 的区别**：来源（第三方移植 vs 官方）、工具链（Vite+Vue vs esbuild）、依赖（有第三方 vs 只有工作区包）、宿主（双宿主 vs 只认底座）、自检（spec-check vs 契约测试）。运行期一视同仁：同一份出厂 bundle。

### 关键改动
